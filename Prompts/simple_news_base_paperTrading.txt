### Proposed Improvements
To enhance the system while meeting your requirements, I suggest the following improvements:
1. **Keyword-Based Directional Analysis**:
   - Develop a robust keyword dictionary (e.g., “earnings beat” → +0.8, “lawsuit” → -0.7) to complement AI analysis, ensuring consistent directional predictions.
   - Store keywords in `config.py` for easy tuning.
2. **Optimized FMP API Usage**:
   - Use FMP’s batch endpoints (e.g., `/stock_news?tickers=...`) to reduce API calls for multiple tickers.
   - Cache historical price data locally (in SQLite) to minimize API calls for technical analysis.
3. **LLM Fallback Strategy**:
   - Implement a priority queue for LLMs: FinBERT (local, no quota) → Gemini → OpenAI → Claude → Grok (if available) → LLaMA (if accessible).
   - Use Alpha Vantage, Polygon, and Tiingo only for news metadata (e.g., sentiment proxies) when LLMs are unavailable.
4. **Technical Analysis Selection**:
   - Use RSI (overbought/oversold), MACD (trend momentum), Bollinger Bands (volatility), and Moving Averages (trend direction) as primary indicators, as they are widely recognized and effective for short-term trading signals.
   - Add Fibonacci retracement levels as an optional indicator for support/resistance confirmation.
5. **Efficient Deduplication**:
   - Store the last processed timestamp in SQLite and use it to filter FMP API queries (e.g., `/stock_news?from=last_timestamp`).
   - Use a hash of article title + URL to ensure no duplicates, even if timestamps vary slightly.
6. **CSV Output Enhancement**:
   - Add a `keywords_matched` column to the CSV to log which keywords influenced the directional analysis, aiding backtesting transparency.
